`runtime/host/src/main.c` is 10,919 lines, contains 37 distinct BlueWake
environment controls and 196 environment-variable references, and mixes
product launch, diagnostics, scripted input, CPU dispatch, scene probes, and
capture policy. This raises regression risk and makes diagnostic code difficult
to prove absent from shipping performance.

**Disposition:** do not refactor speculatively. As the next accepted subsystem
is touched, move its stable diagnostics/configuration behind a typed module and
keep release defaults explicit. New one-off hooks require a removal date or a
promoted subsystem contract.

### TD-005 - Build and optimization pipeline is not iteration-friendly (high)

- The promoted generated-C policy is `-O2` with three evidence-backed `-O1`
  source fallbacks.
- Whole-composite `-O2` at the legacy unit size is blocked by a small number of
  pathological sources that consumed up to 2h53m each.
- A 1,024-instruction partitioned `-O2` composite completed in 65.7 minutes,
  proving optimization is buildable when compiler input is bounded. That
  partition also changes runtime turn boundaries and is not promotable.
- The LLVM path was rejected earlier, but its slowdown predates current
  runtime/profile changes and was never decomposed by owner.

**Disposition:** partition-size, optimization-level, and per-source fallback
controls are implemented and the hybrid is promoted. Its source-correct build
still takes 4h16m. Decouple compile partitions from logical runtime boundaries
when iteration cost becomes the selected owner; do not claim that refactor as a
runtime speedup or promote shortened runtime partitions. Also isolate chassis
sources and flags from generated-unit compile flags: adding one target-wide
include path invalidated all 748 units during the latest edge experiment even
though only chassis code changed.

### TD-006 - Gate and evidence hygiene has drifted (high)

- `scripts/audit_repo.sh` currently fails because 20 files under
  `local-research/` are tracked, despite the ledger claiming P0 pass.
- Private runtime evidence is durable locally but intentionally not pushed to
  GitHub; GitHub backups protect code, patches, and public conclusions, not the
  complete private artifact corpus.
- Several historical gate statements overstate current Omasao reachability or
  human controllability.
- `BLOCKERS.md` retains historical `active` tokens inside chronological
  snapshots. Its authority banner makes only the first dated block current,
  but the old labels still impede machine-readable status until normalized.

**Disposition:** P0 is `REGRESSED` until tracked private evidence is migrated
or the audit policy is deliberately revised. Keep evidence hashes and public
summaries in Git; back up private evidence separately without publishing game
data or cards.

### TD-007 - Product shell and release operations are largely absent (medium)

The app remains environment-driven and developer-oriented. Clean-machine
preparation, user-owned-disc onboarding, settings, diagnostics export,
fullscreen behavior, update-safe saves, notarization, and distribution are not
qualified.

**Disposition:** defer UI polish until runtime speed and one human session pass,
then build the smallest macOS launch/import/settings path needed for external
testing.

### TD-008 - Compatibility coverage is mostly unstarted (critical for release)

Outset and historical Omasao evidence do not establish full-game behavior.
Bosses, dungeons, inventory, maps, optional content, save variants, long
transitions, and start-to-ending coverage remain. Release-scale soak evidence
at final speed also does not exist.

**Disposition:** do not start broad campaign execution while speed prevents
credible play. Once the macOS runtime sustains near-original speed, promote a

### TD-009 - iOS and iPadOS are intentionally deferred

No mobile percentage should be inferred from the macOS host. Touch UX,
lifecycle, memory pressure, physical-device performance, thermals, and signing
remain separate future gates.

### TD-010 - Generated artifacts do not prove the tracked codegen contract (high)

The ignored `generated/full/composite-lib` tree currently lacks
`dolrecomp_block_can_precharge` and `cycle_observation_suffix`, while the
tracked DolRecomp patch and `tests/test_cpu_abi_contract.py` require both. The
native CTest suite can still pass because the private generated tree is outside
Git and that source-level test is not registered with CTest. This makes the
current test count an incomplete statement of generated-code provenance.

**Disposition:** do not weaken the source test. Regenerate the private
composite from the pinned patched translator, verify the suffix/precharge
contract and deterministic hashes, then rebuild the accepted module. Until
that is done, distinguish host/runtime test success from current-codegen
qualification in every ledger entry.

### TD-011 - Neither route owns an accepted frame-pacing service (high)

Route A exposes vsync but has no promoted retrace-derived 30 Hz limiter. Route B
has not yet initialized its first graphics frame. Raw loop throughput and a
headless GX packet are therefore not product FPS measurements.

**Disposition:** add one explicit pacing owner after Route B presents the native
logo frame, then qualify cadence with vsync enabled and disabled. Do not report
native FPS until representative Outset content draws through J3D.
