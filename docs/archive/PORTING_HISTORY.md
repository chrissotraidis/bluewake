PC-inventory strategy and clarified the real dependency: guest interrupt
observation/delivery still depends on generated edge returns. The callback
installation was removed, its inert ABI retained, and the active work moved to
an edge-topology-invariant CPU runtime contract.

The follow-up mutable service recovered the complete route and matched the
first 1,024 deliveries, revealing a hidden GX PE-finish dependency on diagnostic
state along the way. It still diverged later and converted a 67.6% turn
reduction into only a 10.1% CPU gain. That clarified the finish-line design:
ordinary edges must stay local, while generated deadline check sites publish
only events that are actually due.

A still narrower experiment then found the missing early rule: pending
interrupts must yield when execution first reaches a scheduler-safe PC. That
made the first four retraces exact without device servicing, but an indirect
host predicate on every edge still bought only 13.4% CPU. The project therefore
moved from optimizing the callback to avoiding it on ordinary edges entirely.

The generated-side filter completed that test and removed ordinary callback
entry, but user CPU stayed flat. That was the useful negative result: callback
dispatch was not hiding an architecture-scale win. BlueWake closed the entire
translated-C edge-chaining route and opened a formal execution-route review,
selecting one attribution profile of the preserved exact AArch64 LLVM backend.

That profile changed the interpretation of the earlier LLVM rejection. Most
samples belonged to the old monolithic host, old DSP cadence, and old REL alias
path; LLVM dispatch and its hottest budget loop were a much smaller share. Since
the current CPU ABI only appends fields after the old complete prefix, BlueWake
selected a strict current-host compatibility tier before paying to regenerate
the whole native corpus.


## 2026-09-01: The host boundary was more than a clock boundary

The post-O2 return census finally quantified the generated-edge shape: 56.6%
of returns crossed chunks, 31.2% hit the exact budget, and 11.9% were
same-chunk exits. A new composite loop covered all of those edge types instead
of repeating the old direct-call probe. It delivered the expected performance
proof, removing 64.5% of host turns and 60.2% of 700-route user CPU.

It also failed decisively before title readiness. DSP interrupt delivery fell
from 10,281 events to zero because the full host turn contained per-address HLE
and device interception that the composite loop could not see. In particular,
the JAudio DSP boot handshake is armed when the host observes guest PC
`0x803193AC`. Budget and exception checks were correct but incomplete.

The candidate was removed without limit tuning. The performance result keeps
generated-edge dispatch ranked first; the correctness result reframes the
blocker as an explicit generated-edge-to-host interception ABI. A static
inventory now separates CARD, DVD, REL, DSP, interrupt, and callback semantics
from hundreds of diagnostic PC observations before that ABI is attempted.

The first two recovery tiers were deliberately inert. A typed host predicate
centralized semantic CARD/DVD/REL/DSP addresses, then the composite gained a
host-owned yield callback whose absence preserves one dispatch per turn. Both
tiers retained the exact 700 route; 217 tests cover the callback's budget,
exception, miss, requested-yield, and no-progress exits. Actual chaining waits
for a declared route-observation class, so evidence collection cannot silently
be skipped or confused with product semantics again.

## 2026-09-01: O2 reveals the next runtime layer

The exact legacy-boundary hybrid O2 build changed the performance diagnosis,
not just the stopwatch. A live Outset sample reduced generated dispatch from
99.1% of active-main time to about 56%, exposing meaningful cycle/interrupt and
DSP costs underneath. The app still ran only about 242 seconds of guest time in
415.62 seconds, so compilation and boot were no longer honest proxies for
playability.

The profile also forced a correction to the preceding cycle-lifecycle story.
Direct end-turn rebudgeting had been removed, but interrupt-source refresh still
performed the same unusable calculation indirectly after device sync. The loop
therefore reoriented around an explicit source-publication versus
dispatch-budget contract, with exact observation and delivery semantics kept as
the acceptance boundary.

That split passed every route and cycle invariant and reduced Outset wall/user
time by 3.4%/1.7%. It was promoted as a cleaner contract, not inflated into a
playability result. The remaining architecture question returned to the 56%
generated-execution share and the cost of returning through giant per-chunk PC
dispatchers, while the earlier unconditional cross-chunk experiment remained
closed unless a new mechanism preserved exact budget/deadline returns.

## 2026-09-01: Reorienting from research milestones to playability

By September 1, the signed app reliably compiled, launched, and reached Outset
with an exact promoted route. A real GX single-texmap binding defect had also
been fixed. But the route still required 470.60 seconds of wall time to execute
about 235 seconds of guest time, and three attempts to recapture Link through
semantic runtime predicates produced either panorama frames or no frame.

That combination exposed a planning problem: the loop was spending increasing
effort proving local runtime facts while original-speed play, unrestricted
human input/audio acceptance, broad compatibility, and packaging remained
open. Capture timing was frozen, the hair blocker was made inactive pending
direct human re-observation, and a new macOS-playability blocker replaced it.
The next performance work was architecture-scale: one current profile, then
partitioned/per-unit generated-C optimization or a decomposed LLVM
qualification. This historical 35-45% estimate is superseded by the current
20-30% stable-playable estimate in `status/CURRENT.md` and `status/TECH_DEBT.md`.

## 2026-08-31: Correct timing invalidated the old Omasao test driver

The first post-contract optimization followed the independent review's exact
DSP idle-loop proposal. It passed a synthetic adapter fixture and a serialized
700-retrace exact-delivery pair, but only the HALT shortcut activated. The
required long scene tier then exposed a test-driver problem rather than an
optimization result. The first run accidentally used the old 29-point route;
the second reconstructed the accepted 33-point collision detour from durable
logs. Under the promoted guest clock and guest-owned DSP completion, both
runs left the ladder at the same retrace and then missed the very first route
point, entering ordinary retail recovery behavior while distance grew by more
than four thousand units. Neither mounted Omasao, and idle skip remained zero.

This is an important historical boundary: deterministic input is not a stable
acceptance route when a corrected timing contract changes the guest trajectory.
A normal stop and canonical card are insufficient if the intended scene was
never reached. The candidate was removed, route and DSP-signature variants
were closed under anti-stall, and the loop advanced to the independent
cross-chunk publication mechanism using the already-qualified short exact
digest.

## 2026-08-31: Exact final time was not exact interrupt delivery

The first instruction-charge composite was intentionally expensive to
falsify. It regenerated all 416 guest images, linked 748 arm64 translation
units under CPU ABI v5, and passed complete metadata coverage. The three-frame
cap pair improved one important invariant: both runs ended at exactly
24,300,000 guest cycles instead of differing by one. It still failed the
architectural oracle. AI work, final PC, and the saved PC at the first VI
interrupt differed by cap, while the canonical cards and subsystem totals
matched.

The failed candidate exposed a narrower contract error. BlueWake turned on
instruction charging only after the authentic deadline was already inside the
host-turn cap. Before that point, generated code knew the cap but not the
deadline's independent extent, so one prepaid basic block could cross the
deadline from outside the precision interval. This is the entry/overshoot gap
called out by the independent review. The result closed the current candidate
before a 700-retrace run and replaced it with a focused compiler/runtime
fixture: place a deadline one cycle beyond the cap and prove that a multi-cycle
block enters precise execution before crossing it.

The rebuilt cycle-domain composite then reached its first authentic
qualification. Cap 256 completed 700 retraces normally; cap 1,024 preserved
every named gameplay/device/card outcome except the clock/audio-cycle digest
while reducing host turns 22.9%. It ended one guest cycle late and changed the
AI work remainder, so the performance gain remains unqualified. Log comparison
placed the first visible difference at DSP interrupt position before retrace 2.

One host-only falsification removed the last fabricated cycle: zero-cycle HLE
turns no longer advance guest time merely because they passed through the
dispatch chassis. The correction is architecturally necessary, but a
three-retrace cap pair still differed by one final cycle and 1,535 AI work
units. This ruled out host-call fallback as the sole owner and exposed the
remaining granularity mismatch: the generated C backend charges a whole basic
block before executing it, so a block can cross an exact device deadline
before the next check site. The next compiler milestone is an
instruction-cycle deadline path with focused fixtures, not another guard or
cap experiment.

The 2026-08-30 review changed the performance work from cadence tuning into a
clock-contract repair. BlueWake now keeps one absolute guest-cycle timeline:
translated TB, decrementer, and MMIO observations flush only through the
reading instruction, while VI, DSP, and audio synchronize to that same point
through independent cursors. The translator exposes each observation's
unexecuted basic-block suffix, allowing the host to retain future charges
without adding bookkeeping to ordinary arithmetic instructions. Generated
basic-block boundaries also became deadline check sites, and `mtdec` plus
nested callback dispatches explicitly rebudget.

The first implementation checkpoint was not a gameplay acceptance claim.
Extending `CPUState` deliberately invalidated the old composite ABI, so all 206
DOL and 415 REL translation inputs were regenerated; the RELs use the canonical
tagged aperture beginning at `0xC0400000`. The complete 748-unit arm64
composite linked in 4,066.19 seconds wall (20,246.87 user, 515.38 system) with
SHA-256
`bf07dc2f4e5405c713f363b386b99e1f97607c5b25eedb67646e281763f3e771`.
Generator tests pass 18/18 and ABI coverage passes all 417 ranges, 748 chunks,
415 REL modules, and 8,079 REL sections. The next historical milestone is one
authentic cap-256 digest re-baseline followed by cap-1,024 invariance. Only that
result can turn cross-chunk chaining from an unsafe timing change into a
performance dial.

The deadline-aware budget implementation then tested the profile's largest
remaining owner at full-composite scale. All 748 generated units were rebuilt
to consume the ABI-reserved runtime budget while preserving 256 cycles when
the field is zero. A 1,024-cycle policy outside DSP, VI, AI, decrementer, and
pending-interrupt boundaries reduced host turns by 22.7%, but moved two
lazy-FPU restorations and added 32 final guest cycles.

The failure exposed a concrete generated-code constraint: one translated
charge is 1,718 cycles, so a guard equal to the 1,024 budget can cross the very
deadline it claims to protect. One bounded 2,048-cycle overshoot margin fixed
the FPU/collision digest, yet the run still ended 14 cycles and one timebase
tick late. Its matched user CPU was effectively unchanged. Counting the
original fixed probe, three larger-budget experiment shapes now fail exact
delivery, so anti-stall closes cadence tuning. The host returned to 256 and
reproduced every accepted clock, CPU, device, and card outcome on the rebuilt
composite. Only the behavior-neutral ABI capability remains. The next loop
separates Link's visible hair/material error from performance while an
independent architecture audit is requested.

A fresh current-build profile prevented the next decision from relying on
stale ownership. Outset and Omasao each spent about half of main-thread samples
inside translated dispatch, with the nested GX frontend/sink route accounting
for about 12%. DSP had fallen to 11.9% in Outset but remained 30.5% in Omasao.
Texture hashing had disappeared from the owner list, and render workers still
mostly waited. Since Outset was both slower and less DSP-bound, BlueWake
returned to the architectural result of the rejected fixed-quantum probe: use
the ABI's cycle budget dynamically, capped by authentic device and interrupt
deadlines, rather than moving another local helper or sweeping constants.

The immediate full-scene replay then answered the product question. The
shipping build repeated all 3,670,902,066 blocks, every route and scene
milestone, and every named device total through Omasao with an unchanged card.
Against the prior exact-eight full route, the current stack used 22.3% less
user CPU and 23.0% fewer retired instructions. Frame telemetry improved but
remained far from the retail target: Outset measured 6.0 fps median with a 2.5
fps tail, while Omasao measured 13.55 fps median. Light opening scenes remained
near 29 fps in the same binary, turning “the game is slow” into a sharply
scene-dependent GX/dispatch question. The next loop therefore profiles the
current shipping scene before choosing another optimization.

On 2026-08-30, the dispatch-quantum result prompted a less invasive question:
how much of the host boundary was product work, and how much was dormant
instrumentation? Environment values had already been cached, but 28 trace and
watch branches still crossed the exact 256-cycle loop. BlueWake made normal
builds compile those probes out and retained them in an explicit diagnostic
build instead of changing guest cadence.

The matched reverse control preserved the exact 61,469,941-block route, all
clock, CPU, DSP, DVD, ARAM, GX, texture-cache, and card outcomes, while user
CPU fell 19.4% and retired instructions fell 18.7%. The result is meaningful
but bounded: it does not revise the last measured 3-5 fps Outset or 10.6-11.9
fps Omasao observations until a visible shipping-build replay measures them.
The same user review supplied a concrete second product defect, Link's broken
hair/material rendering, which is now separately owned by GX correctness
rather than folded into performance.

On 2026-08-30, the first profile after authentic MEM1 dirty generations
removed texture hashing from the visible title-route owners. It also surfaced
CARD dispatch and FP availability again, but both isolated boundaries had
already failed matched end-to-end timing. Step 0 therefore changed scale. A
DOL-only falsification build raised the translated loop quantum from 256 to
1,024 cycles while reusing unchanged REL objects. The hybrid artifact was
explicitly ineligible for gameplay qualification.

The result proved a real dispatch opportunity: against a matched signed
700-retrace control, host turns fell 23.5%, user CPU 8.5%, retired instructions
10.1%, and host cycles 7.1%. Title/file-select timing and every named DSP, DVD,
ARAM, GX, texture-cache, and card total remained equal. The larger fixed
quantum nevertheless moved two lazy-FPU restorations, created four deferred-FP
collision observations, and shifted the final cycle boundary. It was rejected
at the exact-delivery gate. This is not an invitation to sweep constants; it
assigns the next architectural owner to the ABI-reserved per-dispatch cycle
budget, capped by authentic device and interrupt deadlines. Probe/control
SHA-256: `15aa27be94867cb4907dadb81218bb49c6b05f3377aff7e7a81a72bd3a52c817`
and `a72b5ba1ab87f7ee54a3fc8eb135bfd550e2319661d8879ca8b80ad7aff8fbfb`.

## How to read the record

This file is the milestone-scale story for readers who want to understand how
the port was built. [`status/CURRENT.md`](status/CURRENT.md) is the live
engineering frontier, [`status/BLOCKERS.md`](status/BLOCKERS.md) preserves the
accepted and rejected blocker evidence, and
[`status/DECISIONS.md`](status/DECISIONS.md) records architectural choices.
Dated reviews and reorientations remain in `status/` so later conclusions do
not erase the evidence that changed the project's direction. Commit history
supplies the implementation-level record.

The history deliberately records wrong turns and superseded hypotheses as
well as successes. Those transitions explain why the runtime has its current
architecture and preserve lessons that would otherwise disappear into a list
of commits. Exact counters, artifact hashes, and reproduction commands remain
in the status ledgers so the narrative can stay readable without weakening
its evidence trail.

## August 9-13: From WAIT to a bounded prototype

The first audit concluded **WAIT**. Wind Waker's hundreds of dynamic REL
modules, incomplete matching decompilation, audio stack, Apple platform
constraints, and lack of gameplay evidence made a complete product promise
unjustified.

A second review changed the decision without pretending those risks had
vanished. Newer DolRecomp and RecompCore evidence showed that a Mac-first,
no-runtime-PowerPC-JIT experiment could answer the largest unknowns. BlueWake
therefore adopted a bounded static-recompilation prototype, with authentic
gameplay as the point at which iOS and iPadOS work could begin.

Evidence: [`FEASIBILITY_REPORT.md`](FEASIBILITY_REPORT.md) and
[`FEASIBILITY_REASSESSMENT_2026-08-13.md`](FEASIBILITY_REASSESSMENT_2026-08-13.md).

## August 21: Building the complete static image

The first implementation day established reproducibility and the private-data
boundary, then processed the whole executable inventory:

- P0 pinned dependencies, CI, repository audits, and provenance rules.
- P1 extracted 416 executable images from the private disc: one DOL and 415
  REL modules.
- P2 translated all 416 images, with zero unknown instructions in the audited
  output.
- P3 generated and linked one deterministic arm64 composite module containing
  748 code chunks and about 1.95 million translated labels.

This was compilation proof, not boot proof. The next phase had to reconstruct
the GameCube runtime contracts around that translated code.

Evidence: [`status/GATES.md`](status/GATES.md) and the commits ending in P0,

## August 22-24: Runtime reconstruction and a costly wrong turn

Early P4 work implemented guest memory, exception and scheduler context,
dynamic REL mappings, DVD/resource flow, controller delivery, and the first GX
path. The route advanced through authentic initialization and began producing
original boot graphics.

The project also stalled. Dozens of increasingly narrow probes chased
algebraically incoherent ARAM/heap values that appeared only under an optional
timer workaround. An external reorientation showed that the allocator was a
downstream victim: timebase advanced by fabricated block counts while the
decrementer was an opt-in, incoherent service. BlueWake stopped the heap hunt,
promoted one cycle-based guest clock and decrementer subsystem, and amended its
goal loop so repeated experiment *shapes* trigger escalation even when the
commands differ.

That episode became a durable engineering rule: evidence from a rejected
workaround cannot block the authentic route, and incoherent downstream values
should be escalated to the clock, translator, ABI, or other owning subsystem.

Evidence: [`status/REORIENTATION_2026-08-22.md`](status/REORIENTATION_2026-08-22.md)
and [`GOAL_LOOP.md`](../GOAL_LOOP.md).

## August 24-25: Native graphics, audio, and coherent device cadence

The host connected the retail GX FIFO to Aurora and assembled a signed native
`BlueWake.app`. Original Nintendo and Dolby boot content rendered on Apple
Silicon. Controller data reached the retail SI/PAD path, and event-synchronized
input replaced guessed retrace pulses.

Audio investigation then integrated a donor Dolphin DSP LLE core. The retail
Zelda microcode booted, exchanged authentic mailbox tasks, mixed frames, and

silence during splash screens was not an audio failure. More importantly, it
found that VI and AI cadence still advanced by dispatched blocks while guest
time advanced by generated cycle charges. Promoting VI, PAD, and AI onto the
same guest-cycle clock made boot pacing coherent and made later observations
comparable.

## August 25-26: Title, file creation, and the visible opening

With scheduler, callback, device cadence, DSP, and input contracts aligned,
the donor-backed route reached the title screen. Original event ownership then
drove file selection, new-game name entry, and the opening-scene request. The
signed macOS app mounted `Opening.arc` and visibly presented the first retail

The opening initially looked stuck because its text has no new-game skip or

## August 27: Natural completion and the first play scene

The source/data-bounded authentic run matched the timing oracle: opening state
42 arrived at retrace 13,931, state 44 completed at 13,961, and the retail game
requested `PLAY_SCENE` at 14,021. Original play-scene code mounted the sea
stage and Outset object archives and began constructing actors.

The next stop was concrete and upstream-owned. `d_a_npc_md.rel` existed and
was valid, but the raw-REL staging window had no large enough contiguous gap.
BlueWake replaced monotonic placement with owner-aware bounded first-fit and
ran the entire authentic route again. Nineteen minutes later, the result
falsified the allocator hypothesis at precisely the same actor boundary.

The failure then became algebra instead of intuition. The aligned module
needed 119,136 bytes. Even with every dynamic slot removed, 102 fixed REL
data/BSS aliases left a largest possible gap of only 113,648 bytes. The host
had eagerly installed aliases for all translated modules at startup, although
the retail game loads those modules dynamically. First-fit was behaving
correctly inside an impossible address-space policy. The active work therefore
moved upstream again: fixed data/BSS aliases must become module-owned and live
only across the authentic REL load/unload lifetime. This is also why failed
hypotheses remain in the history: the complete control converted a plausible
allocator fix into a measured architectural correction.

The first implementation of that correction passed unit contracts and a short
authentic smoke, then failed the mandatory 65-million-block equivalence tier.
Lazy data aliases let `d_a_ship` use raw executable addresses beginning at
`0x81E000F4`; when `d_a_title` later loaded, its linked AOT code began at
`0x81E000DC`. One numeric PC now named two different modules. Constructor
dispatch repeatedly selected ship lifecycle code and title-ready never arrived.
An attempted reservation of the incoming module's own data ranges did not
change this cross-module code collision, so the experiment stopped after one
bounded lifecycle trace.

BlueWake reverted the candidate and reran the recovery oracle. Ship and title
returned to their prior noncolliding raw addresses, and title-ready returned at
the exact established retrace and block count. The failure refined the owner
again: lazy storage is necessary but insufficient until the authentic link
boundary publishes canonical linked section addresses and removes raw/linked
PC ambiguity. Recording this rollback is part of the method too; a short smoke
can admit an experiment, but only the next qualified tier can promote it.

The next bounded design pass separated those concerns. BlueWake published only
executable section addresses canonically, kept constructor tables in the retail
raw image, and staged raw REL files in a metadata-proven unused tail. Ship and
title then coexisted and title-ready returned at the exact reference retrace.
The first title render exposed a deeper collision: a live J3D material and its
color block occupied addresses that the generator had independently assigned
to module 60 code and BSS. A no-input control and a narrower BSS-residency
implementation produced the same zero-vtable terminal. The experiment was
removed rather than patched around another address. The historical conclusion
is architectural: authentic OSLink publication needs a generated REL virtual
address namespace disjoint from retail MEM1, not increasingly clever ownership
rules for overlapping numeric addresses.

That long replay also exposed a host-side throughput cost rather than a guest
stall. Native sampling found the donor DSP instruction loop repeatedly reading
environment configuration and trace-only mailbox, DMEM, and IFX state even
when tracing was disabled. BlueWake cached immutable trace configuration and
gave trace-off execution a behavior-equivalent fast path. The check uncovered
a second issue: Release `NDEBUG` had compiled away the assert-based DSP adapter
tests. Their real bodies now run in Release, with stale reset, task-memory, and
mailbox oracles corrected against the pinned donor; trace-on and trace-off
paths both pass.

Removing that first bottleneck exposed a broader one: disabled diagnostic
branches still called `getenv()` throughout dispatch and GX MMIO. A second
native profile placed 3,022 of 4,202 main-thread samples in environment-table
locking. Caching those immutable flags at startup preserved exact retail
milestones and block counts while reducing a 65-million-block authentic run
to 301.64 seconds, about 4.6 times faster than the replay it replaced. This is
part of the porting method: long controls are profiled as systems, and host
overhead is removed only when an equivalence run proves that the guest-visible
route did not change.

One more profile moved the bottleneck into memory translation. Each ordinary
DOL RAM access scanned 1,901 fixed REL aliases before falling back to main
memory. The runtime now tracks only the aggregate minimum and maximum alias
bounds, rejecting impossible lookups before retaining the original ordered
scan for possible hits. A second equivalence control reduced the same 65
million blocks to 120.99 seconds with every retail milestone unchanged. The
change is stored as a public dependency patch, so the optimization and its
regression test can be reconstructed without the private checkout.

The address-space correction then became concrete. BlueWake regenerated every
REL into a tagged virtual aperture beginning at `0xC0400000`, preserving each
module's low address bits and relative branch distances while making generated
code, data, and BSS numerically disjoint from retail MEM1 and the raw staging
window. Generator contracts reject any future REL layout that overlaps either
retail region, and both the translator and runtime now preserve exact tagged
addresses instead of collapsing bit 30 during branch relocation or alias
lookup.

The first title run did not pass cleanly. It reached `d_a_title`, then exposed
an algebraically coherent integration mistake: tagged REL code arrived at the
DOL constructor-registration API as `0xC0241178`, while an older host lifecycle
bridge compared only against canonical `0x80241178` before the generated
dispatcher had a chance to canonicalize it. Extending that existing bridge to
recognize both views removed the malformed constructor terminal. The corrected
candidate ran normally through 25 million blocks, loaded ship and title, and
continued into broad room and actor creation. This is an admitted architecture
checkpoint, not yet a playable-game claim; the complete donor-backed
opening-to-Outset replay remains the promotion gate.

The next full no-input replay corrected an important overclaim: running for
800 million blocks without a crash was not title qualification because the
title process had never been created. A focused profile trace showed why.
BlueWake had installed exact tagged aliases for REL BSS, but file-backed REL
data still fell through the runtime's physical-address fallback. Later dynamic
loads overwrote that raw staging memory, turning a valid title profile into
PowerPC instruction words. Extending the same exact-alias ownership to every
linked storage section restored the original profile and title execution.

Authentic title input then advanced far enough to expose one more generator
contract error. `d_a_kanban` returned through a null destructor because its
generated code used BSS at `0xC09A4470` while the composite metadata advertised
`0xC09A4480`. The difference was not actor logic: the REL file is exactly
`0x4470` bytes and declares 8-byte BSS alignment, but BlueWake had independently
rounded every BSS image to 32 bytes. The generator now reads the REL header and
uses DolRecomp's alignment rule in both of its metadata paths. A regression
fixture deliberately uses a nonaligned file length so a fixed alignment cannot
silently return.

That correction produced the first extended tagged run with genuine forward
progress: title-ready at retrace 333, name-scene creation at 451, memcard check
at 459, file select at 649, and new-file-slot input at 690. It stopped normally
at the retrace-700 bound after 59,696,337 translated blocks. Temporary
module-specific probes were removed once the shared contract was proved. The
historical lesson is the same one that shaped the earlier clock reorientation:
long execution is not a milestone by itself; ownership and guest-observable
state decide whether an experiment actually exercised the gate.

The complete promotion run then closed the address-space chapter. The tagged
route replayed name entry and every autonomous opening state, reaching state
42 at retrace 13,935, opening completion at 13,965, and `PLAY_SCENE` at 14,025.
This time `d_a_npc_md` materialized successfully at raw staging address
`0x81E48540`; original code continued through many later actors, mounted
Outset's `Stage/sea/Room44.arc`, and completed the scene overlap. The process
stopped normally at exactly 800 million blocks, with no DVD failures, ARAM
rejects, or unmapped PC. The generated tagged namespace was promoted and the
REL representation blocker resolved.

That result is a large boot milestone, but it is not yet a claim that BlueWake
is playable. The proof was headless. The next owner is the product boundary:
the signed macOS app must visibly present the same Outset state through Aurora
and sustain native controller input, audio, and frame delivery. iOS and iPadOS
remain deferred until that macOS route is stable.

The first product-boundary replay then requalified the tagged route in the
signed app rather than assuming headless equivalence. Aurora rendered the
original Nintendo boot logo, the runtime reached title-ready at retrace 333,
and event-owned input reproduced file selection, name entry, and opening
creation. The scene-overlap capture initially sampled a legitimate black
transition at retrace 954; a bounded repeat using the existing first-nonblank
monitor kept observing without changing guest state. At retrace 1,088, five
retraces after opening state 3 began, the readback visibly contained the first
retail narration. The run stopped normally at retrace 1,200 with zero GX
failures. This closes only the first native-presentation tier. The historical
frontier is now sharper: original retail code reaches Outset headlessly and
renders through the opening natively, but visible Outset and sustained player
control still require evidence.

The first full native Outset attempt preserved every guest milestone through
opening completion, `PLAY_SCENE`, `Room44.arc`, and scene-overlap phase 6. It
then aborted immediately after the requested Outset readback. The adjacency
was misleading: the macOS crash stack placed the abort in Aurora's index-data
push for a gxcore draw, not in framebuffer readback. Aurora's fixed, non-owned
per-frame index staging slice deliberately aborts when it exceeds 8 MiB, and
the transition crossed that capacity before the next retail display copy.
This is useful historical progress despite the crash: native game execution
reached Outset, and the remaining failure moved cleanly into the presentation
owner. The next candidate doubles the promoted index budget to 16 MiB while
preserving every draw; the complete native replay, not unit tests alone, will
decide whether that capacity is sufficient.

That first capacity diagnosis was wrong. Doubling the index slice reproduced
the abort at the same guest point. Rather than increasing another number and
running the same twelve-minute experiment blindly, BlueWake symbolized the
exact return address in the signed arm64 binary. It lands immediately after
`push_uniform(plan.constants, 0x910)`: the unchanged 24 MiB uniform slice was
the first exhausted resource. The blocker was reframed from one index boundary
to Aurora's fixed frame-staging budget. The next candidate sizes uniforms,
vertices, indices, and storage proportionally for the measured scene burst.
This failed inference is preserved because it shows the practical difference
between a plausible stack-level guess and instruction-level ownership.

The proportional budget finally crossed the original terminal and produced a
post-transition readback at retrace 14,112. It contained Outset sky and cloud
geometry, but large black regions made the presentation incomplete. The host
continued another twelve million translated blocks and then exhausted even the
48 MiB uniform slice at the same `push_uniform` call. That result rejected
fixed-capacity growth altogether. More memory can postpone an unbounded host
frame; it cannot supply the missing lifecycle boundary. The owner is now
Aurora staging segmentation: submit accumulated GPU work and renew mapped
buffers while preserving the EFB and render-pass semantics, without inventing
a retail display copy or presenting a partial frame. The partial image still
matters historically because it proves that native original-game execution did
reach Outset; it does not yet prove correct presentation or playability.

BlueWake then implemented the lifecycle boundary instead of another larger
number. Before pushing any part of a gxcore draw, Aurora now projects the whole
vertex/index/uniform request and reserves enough uniform headroom to finish the
pass. A full segment finalizes the EFB work, submits it without touching the
surface, renews mapped staging, and resumes with color and depth load semantics.
The original bounded staging sizes return, avoiding the permanent memory cost
of the rejected 2x budget. A pure over-capacity/reset contract and a short
native smoke admit the candidate; only the complete Outset replay can promote
it.

The complete replay promoted that architecture. Twenty staging segments
carried the signed native process through the same opening completion,
`PLAY_SCENE`, Room 44 mount, and overlap completion that had already passed
headlessly. At 800 million translated blocks the process stopped normally,
after more than one million GX submissions with no rejected or failed draw.
This sharply separates two conclusions that would be easy to blur together:
the staging crash is solved, but the first readback only twelve retraces after
overlap completion still looks transitional, with substantial black regions.
BlueWake therefore records the lifecycle repair as promoted while leaving
clean Outset presentation and player control open. The history is meant to
show these partial promotions, including the attractive wrong turns, rather
than retroactively presenting the port as a straight line.

A later readback rejected the simplest remaining visual explanation. Fifty-four
retraces after overlap completion, the image still contained the same broad
black regions. The retail source makes that conclusion stronger and more
precise: the opening requests `OVERLAP0`, whose fade-in and fade-out legs each
last 26 executions; the logged fade-out phase had already consumed 56 retraces
before phase 5. The image therefore was not merely caught inside that overlap
fade. At this point the loop deliberately stopped moving the screenshot
boundary. gxcore
already maintained cumulative counters for skipped and unsupported draws and
for EFB/display copies, but exposed only a subset through noisy opt-in logging.
Those counters became a single default shutdown health report. The next replay
can now assign the malformed image to draw translation or framebuffer
ownership before another graphics implementation is attempted.

That assignment was immediate and quantitative. The authentic route observed
thousands of display and EFB texture copies, but gxcore skipped 325,822 of
1,302,398 planned draws, all at its vertex-decode boundary. The image was not
being lost after a complete translated scene; roughly one quarter of the
scene's draw plans never reached GPU submission. BlueWake retained the compact
default report and subdivided the eight already-existing decode exits, making
the next replay a contract classification rather than a per-draw trace.

The classification initially appeared to collapse to one cause: every skipped
draw reached the zero-index topology exit while projection capture, payload
walking, indexed arrays, bounds, and stride all reported zero failures. That
exit was labeled as line/point unsupported, so BlueWake admitted lines and
points through native WebGPU topology and expanded strips into explicit pairs.
The full replay then produced the exact same counters and the exact same frame
hash. The label had hidden a broader condition: empty, unknown, and incomplete
triangle or quad batches also return zero indices. The line/point inference was
wrong, and the candidate was not promoted. This correction is historically
important because it is another example of an aggregate counter naming a
symptom more narrowly than the code actually defines it. The loop now returns
to a pure plan-builder contract and primitive/count classification rather than
running a fourth near-identical visual experiment.

The first reframed step stayed entirely inside a pure gxcore fixture. A valid
line plan and valid point plan both produced indices and the expected pipeline
topology; a three-vertex quad reproduced the shared zero-index exit. The
default health report was then split by primitive class. This made the next
authentic run a batch-contract classification, not another attempt to infer
ownership from an unchanged picture.

That split assigned every zero-index exit to quads and none to any other
primitive. Because the payloads were nonempty and Aurora's own builder emits
quad indices only in groups of four, these were incomplete-quad no-ops, not
missing geometry. The apparent quarter-of-scene translation loss was entirely
a health-counter taxonomy error. BlueWake corrected the report so recognized
incomplete primitives count as no-ops while unknown topology remains a real
failure. This sequence is retained in full because it shows why even a precise
large number can mislead when its category does not match the implementation's
algebra.

Returning to the pixels after eliminating that attractive numerical lead
changed the shape of the next question. The frame is not uniformly dark: it
contains cloud-textured geometry surrounded by opaque black in regions that
look transparent. That morphology points narrowly toward texture alpha, TEV
alpha/compare, or blend translation. It is not yet a diagnosis. The next tier
is a public pixel-exact alpha-compositing fixture, not another full replay at a
slightly later screenshot boundary. This is the kind of course correction the
history is intended to retain: the evidence trail includes both what BlueWake
learned and what apparently decisive measurements turned out not to mean.

The public GPU fixture then rejected that general alpha diagnosis. It rendered
an opaque background through the real gxcore/Aurora path and composited a
two-texture, two-coordinate TEV material whose second texture supplied alpha
bands of 0, 128, and 255. Pixel readback preserved the background at zero
alpha, produced the expected blend at half alpha, and produced opaque color at
full alpha. The draw plan also bound both expected texture maps. General RGBA8
texture alpha, TEV alpha multiplication, alpha comparison, multi-texture
binding, and `SrcAlpha`/`InvSrcAlpha` blending therefore work together in the
actual GPU path. The malformed Outset frame needs a more specific material,
texture-format, scene-layer, or reference-composition explanation; changing
the general blend path would not be evidence-led.

The next replay exposed a different kind of failure before it could answer the
graphics question: the canonical private dylib filename no longer identified
the qualified tagged composite. The file on disk exported all REL storage in
the old untagged retail-memory range, and a freshly rebuilt host consequently
remained in the logo scene. BlueWake stopped at the early title-equivalence
gate, inspected the dylib's exported metadata, and regenerated all 415 RELs
from the pinned translator command into the promoted `0xC0400000` aperture.
The clean 748-chunk link passed ABI coverage and reproduced title-ready at
retrace 333. This recovery adds a durable lesson to the method: source and Git
history preserve how to build the port, but long native evidence also depends
on identifying ignored private-derived artifacts by exported namespace and
hash, never by a familiar path alone.

With artifact identity restored, one default-on ownership classifier finally
answered the scene-layer question without another screenshot. After authentic
`PLAY_SCENE`, the retail BG draw wrapper ran 154 times; VRBOX, VRBOX2, and SEA
each ran 79 times. Their first gameplay callbacks occurred at retraces
14,043-14,044, before the qualified run stopped normally at retrace 14,200.
The opaque-black world is therefore not explained by room or sea actors being
left out of process scheduling. Ownership moves downstream into the first
absent J3D material's draw-buffer path or a specific GX contract. The same
shutdown report provides bounded leads, not verdicts: TLUT textures,
indirect-texture plans, and unsupported texgens are present and now require
material-specific correlation before implementation.

That correlation identified indirect texturing as the first concrete missing
GX contract. BlueWake did not begin with the full game replay. A public
gxcore/Aurora fixture rendered a striped texture through a retail-format
indirect matrix chosen to move the sample by exactly one texel. The old path
returned the unshifted red pixel and counted the plan as ignored; the new path
returned the exact green pixel. The promoted subsystem carries indirect
orders, scales, matrices, fixed-point bias and format, coordinate wrapping,
add-previous, bump alpha, and every referenced texture map into generated
WGSL. Its focused pixel oracle, gxcore shader contracts, complete host test
suite, signed app build, and repository audit all pass.

The authentic replay then supplied the distinction a fixture cannot. Original
retail execution again completed the opening, entered `PLAY_SCENE`, and crossed
the Outset overlap before stopping normally at 800 million blocks. gxcore
executed 1,604 indirect plans and ignored none. At the same late capture
boundary, nonblank coverage increased from 696,459 to 1,040,931 pixels, so the
new capability materially changed the rendered scene. Direct inspection still
showed broad black world regions, however. Indirect TEV was therefore promoted
as a genuine fidelity advance, not declared the whole solution. The active
question moves to the first absent material's remaining texgen/source-row or
depth contract. This is another reason to keep a historical record: a feature
can be correct, necessary, and measurably useful without being the final fix
that motivated its investigation.

The next aggregate was deceptive in a different way. The shutdown report's
`unsupported_texgen` total mixed a hard four-coordinate cap with a condition
that already had a supported cached fallback, while regular normal-source
coordinates were not counted at all. Splitting count and source-row ownership
revealed 1,015 normal-source plans and 234 over-cap plans. Every other source
class was zero. Dolphin's generated and software vertex paths supplied an
exact normal-source oracle, so BlueWake implemented it behind a pure shader
contract: use the raw vertex normal when present and preserve the initialized
coordinate otherwise.

All 1,015 retail plans exercised the new path, but the qualified frame was
byte-identical to the control. The implementation remains a correct promoted
capability; the pixel result rejects it as the current Outset owner. The same
run made the next boundary unusually crisp: every one of the 234 remaining
gaps requests five texture coordinates, while requests for six, seven, or
eight are zero. Native replay now stops. The next step returns to a pure
five-texgen layout and shader contract before the fixed four-coordinate slice
is expanded. This pair of results is retained because it demonstrates two
different reasons counters mislead: one category can combine supported and
unsupported states, and another important state can be absent from the
category entirely.

The five-coordinate contract then failed exactly where expected and was
promoted through the full path: CP/VAT decoding, a stable expanded vertex
layout, MatrixIndexB selection, generated WGSL, Aurora input state, and TEV
sampling. All 234 authentic five-coordinate plans became supported with no
texgen overflow, and two native Metal fixtures plus the complete host suite
remained green. Yet the synchronized Outset frame was again byte-identical.
This closed a real renderer gap without changing the visible failure and
removed texgen count from the causal frontier.

The verification also preserved an ordinary but important mistake. The first
promotion run completed cleanly but used the wrong framebuffer-output
environment key, so it produced valid runtime counters and no valid visual
artifact. It was recorded as such, and a corrected unchanged replay recovered
the image. The distinction matters historically: a successful process exit is
not evidence for an artifact the command never requested.

With every counted gxcore feature gap now zero, the next chapter changes
method rather than tracing another nearby boundary. The remaining black world
is treated as a semantic mismatch in an admitted path. Work returns to donor
conformance for depth, blending, channel writes, and final TEV output, with a
focused oracle required before another full native capture.

The first semantic audit found a real omission in destination alpha. Wind
Waker's frame compositor performs alpha-only writes through BP register `0x42`
and consumes that stored alpha in later color blends. gxcore had decoded the
blend factor but never forced the EFB alpha value. A public three-draw Metal
oracle made the failure unambiguous: blue background, forced zero alpha, then
red blended by destination alpha should remain blue; the old path returned
red. The promoted implementation uses Dawn's dual-source blending so the
forced EFB alpha and original TEV blend alpha remain distinct, matching the
Dolphin model.

The authentic route exercised 395 destination-alpha plans without a pipeline
failure, but Outset remained byte-identical to the prior control. This was
another useful closure: the reduced renderer now handles a game-used
compositing contract correctly, while the historical record prevents that
correctness result from being confused with progress on the visible black
world. The causal frontier moves to raster-color and lighting semantics, where
an admitted but incorrect value can blacken a material without any gap counter.

That lighting audit began by checking state lifetime rather than adding a new
material trace. XF channel, material, and light registers were already
persistent across FIFO and display-list boundaries, and gxcore's integer
lighting equations matched Dolphin. One matrix-selection mismatch remained:
when vertices carried PNMTXIDX, position used each vertex's matrix while
lighting and emboss used one draw-wide normal matrix. Dolphin instead indexes
its 32-row normal bank with every vertex. A focused shader oracle failed on the
old path, and the promoted implementation carried the complete XF bank through
the uniform ABI and real Metal compilation.

The authentic game exercised the correction 96,098 times, far more often than
several earlier renderer fixes, without a rejected draw or changed milestone.
Even so, the synchronized Outset frame was byte-for-byte identical. That result
is historically useful because exercise count is not causal ownership: a
heavily used contract can be genuinely wrong yet visually neutral at the
chosen frame. The fix remains part of the renderer, while the active question
moves from lighting to J3D raster-color and TEV raster-channel selection.

That raster-channel audit closed cleanly: TEV order, raster source selection,
swap tables, missing-channel fallback, channel-count zeroing, and final-stage
destination routing all matched Dolphin. The useful mismatch sat beside the
audited state instead. gxcore ignored BP register `0x43` bit 6, the
`GXSetZCompLoc` choice that asks the pixel engine to update depth before alpha
testing. A state oracle first proved the bit was absent from the pipeline key.
The public GPU oracle then needed its own correction: placing the geometry at
the reversed-Z clear value made the strict comparison reject both candidate
draws and falsely pass blue. Moving it to depth 0.5 made the old renderer fail
green and the corrected renderer pass blue.

The first real prepass implementation produced a valuable crash rather than a
pixel. Dawn's Metal backend trapped in `BindGroupTracker::ApplyBindGroupImpl`
because the depth pipeline inherited texture/TEV bind-group state it did not
consume. The retained macOS report for incident
`6AD5B93E-50AA-494F-89AC-2AF365220ACB` records that exact failed fixture; its
SHA-256 is
`003621286218d25a99ba396e36fcea4a57f7cf9c55934da6fd28f32788f5e034`.
Restricting the depth layout to vertex groups 0 and 1, then rebinding its
dynamic vertex uniform after each pipeline switch, removed the incompatibility.
The public fixture and all prior Metal fixtures now pass serially. BlueWake
retains this failure because the crash identified a backend contract that a
fragmentless or nominally minimal shader alone did not make safe.

The authentic replay also distinguished host plumbing from guest evidence.
Its first launch stalled in CoreAudio teardown before BlueWake booted and was
discarded. Repeating the same qualified route with SDL's dummy host speaker
sink left the donor DSP, guest cadence, rendering, and input path intact; the
first nonzero DSP DMA still arrived at retail retrace 354. That admitted run
completed the opening and Outset transition normally and exercised 685,858
early-depth plans without one GX failure. Nevertheless, the synchronized frame
was byte-for-byte identical to the prior control and retained the same broad
black world regions. Early depth is therefore promoted as correctness, not as
the visual owner. Its current whole-draw two-pass implementation is also
documented honestly as an approximation of true per-fragment early-Z for
overlapping or blended primitives. Once again, frequency of exercise did not
establish causality.

The next donor comparison stayed in blending but separated the EFB's logical
format from the host surface. Dolphin writes destination alpha only in
RGBA6_Z24; RGB8 and RGB565 behave as though destination alpha is permanently
one. gxcore instead allowed guest alpha writes into its always-RGBA host target
and later consumed that accidental value. It also carried one pair of blend
factors for both RGB and alpha, where the donor derives component-specific
factors. A pure key oracle exposed the existing contradiction directly: its
RGB8 case had asserted an alpha write was enabled.

The public destination-alpha fixture grew into a two-region contract. Its left
half retains the earlier forced-alpha test. On the right, an RGB8 draw attempts
to poison host alpha with zero before a red draw blends by destination alpha.
The donor rule leaves the result red; the old state would multiply by the
poisoned zero. The promoted path gates writes on RGBA6, substitutes one for
destination alpha in no-alpha modes, and carries independent alpha factors to
WebGPU. All focused and native tests passed, and the complete authentic route
again reached Outset without a failure. The synchronized frame was nevertheless
byte-identical. This is another durable renderer correction and another closed
visual hypothesis, not a reason to move the capture boundary.

The next Step-0 comparison found a draw-state omission rather than a shader
formula error. gxcore retained the BP scissor registers, but its draw plan had
no place for them and the shadow frontend never called Aurora's logical
scissor API. The first focused oracle failed at compile time because those
fields simply did not exist. The promoted implementation follows Dolphin's
inclusive bounds, default SDK bias, 1024-pixel offset wrapping, EFB clipping,
and viewport-overlap/area tie-break. A native quadrant fixture makes the
behavior visible: a full-screen green draw clipped to the top half must leave
the lower blue and red regions untouched; ignoring scissor turns the entire
frame green.

All focused, contract, Metal, build, and signing checks passed, and the
authentic 800-million-block route completed without a GX failure. The Outset
capture was again byte-for-byte identical. This promotes a real draw-time
contract while closing scissor as the owner of the current black world. It
also reinforces the loop's anti-stall rule: after a focused donor mismatch is
proven and its synchronized artifact is unchanged, the next iteration changes
subsystem shape instead of moving the same capture boundary.

Changing shape from draw state to copy lifecycle exposed a more structural
error. Both the C replay parser and C++ retail frontend reused one width/height
pair for the persistent BP source rectangle and the per-trigger destination.
When half-scale was enabled, the first trigger replaced 8x8 with 4x4; a second
unchanged trigger then incorrectly halved that stored result to 2x2. Hardware
does not rewrite BP `0x4A` when a copy fires. The focused contracts encoded
that algebra directly and failed before the fix in both routes.

The promoted state now keeps source and destination dimensions separate, so
repeated triggers remain 4x4 until the guest writes a new source rectangle.
The complete build and authentic route stayed stable, but the synchronized
Outset frame did not change. This closes another admitted lifecycle mismatch
without confusing algebraic correctness with visual ownership. The next loop
must leave repeated EFB-copy variants and inspect a different subsystem.

The next material-state audit found that the shadow renderer discarded every
BP texture-unit sampler and substituted one repeat/linear sampler. The
promoted path now carries each texmap's hardware address and filter modes, LOD
clamps, and supported anisotropy through flat and multi-texture bindings. A
clamp-sensitive Metal fixture proves the state reaches actual pixels rather
than stopping in the plan.

The authentic Outset replay exercised the correction without changing the
guest route or draw totals. Its synchronized frame changed only 369 pixels and
added 12 nonblack pixels; the large opaque-black regions remained. That small
edge-level delta is useful evidence that sampler state is live, but not that it
owns the missing world. True mip-chain uploads and LOD bias remain future
texture work, and the next Step-0 audit must change semantic shape again.

The next audit separated texture-coordinate rasterization from texture-unit
sampling. Wind Waker's J3D display lists write BP SU S/T scale for each active
coordinate, and Dolphin converts the perspective-correct interpolant into a
seven-bit fractional fixed-point value before choosing a texmap. gxcore had
instead sampled the interpolant as an already normalized coordinate, which is
only equivalent when SU scale happens to match the selected image dimensions.
A focused oracle first failed because no SU state existed. The expanded Metal
fixture then paired a 4x4 texture with S scale 3 and proved the difference in
actual pixels.

The promoted path applies those fixed-point coordinates to both direct and
indirect TEV samples and advances the persisted pipeline-cache schema because
the WGSL and pixel-uniform layout changed. The complete authentic run exercised
more than one million scaled plans, with 58,668 real SU/image mismatches, and
finished with exact milestone and draw parity. Its synchronized frame changed
153,514 pixels, mainly across already visible cloud and sky edges, but gained
only 137 nonblack pixels and retained the opaque-black lower world. SU delivery
therefore remains as a substantial correctness fix without owning the blocker.

The next audit changed semantic shape from sampling to framebuffer depth.
Wind Waker's `JFWDisplay::clearEfb` uses an exact 4x4 Z24X8 texture and BP
ZTexture REPLACE to write far depth; gxcore had ignored both ZTexture registers
and used the clear quad's geometry depth. A headless oracle first failed on the
missing fragment-depth contract. The promoted implementation decodes type,
operation, and bias, reconstructs depth from the final raw texture sample, and
maps it through Aurora's established reversed-Z convention. A native Metal
fixture using the retail texture bytes proves the resulting depth attachment
behavior.

The complete authentic replay exercised 36 late ZTexture plans with no ignored
forms, no submission failures, and exact opening-to-Outset milestone parity.
Its synchronized frame was byte-identical to the SU control, so this is another
verified renderer correction rather than the missing-world solution. That
negative result is historically useful: the visible black regions are not
caused by the omitted JFW far-depth clear contract.

The next source comparison separated the two extents of a scaled EFB copy.
Wind Waker's fades and menu captures commonly copy a 640x480 EFB rectangle into
a 320x240 mipmapped texture. The frontend retained both sizes, but only the
destination dimensions crossed the render packet, so gxcore built its source
rectangle from 320x240 and cropped the top-left quarter. A compile-first oracle
made the missing fields explicit; the promoted path now carries source and
destination extents independently through the default runtime and GPU command.
A four-quadrant Metal fixture proves that every corner of the full source
survives the half-scale copy.

The full test, build, signing, and audit gates passed, followed by two normal
authentic signed-app replays. The synchronized Outset frame changed strongly
and gained visible water detail, proving the corrected path is live, but most
terrain remained opaque black. This promotes the scaled-copy contract while
falsifying it as the complete visual owner. The same audit rejected general XF
post-matrix support as the next experiment before implementation: the common
J3D world path uses `GX_PTIDENTITY` throughout and the opening trace contains no
post-matrix loads. That negative source result prevented another speculative
renderer patch.

## August 28: The black world becomes Outset

The next Step 0 pass stopped guessing at aggregate renderer counters and decoded
Outset Room 44's private BDL state directly. All eight terrain materials use the
same compact program: an unlit vertex-color channel, a first TEV stage that
reconstructs that raster shade, a second stage that multiplies one CMPR texture,
and white fog. VTX1 contains 192 nonzero grayscale RGBA8 colors. A bounded
draw-light observation agreed: after the Outset frame boundary there was no
active light with a nonzero mask. This rejected TEV parsing, black fog, and
active lighting without opening a third boundary trace.

The adjacent EFB lifecycle comparison did expose a concrete mismatch. Aurora
keeps copy allocations keyed by destination, dimensions, and format, then binds
the latest allocation by destination. gxcore had only the latter map, so a guest
destination reused for a new shape or format retained the incompatible first
GPU texture. The public half-scale fixture was extended to poison a destination
with 160x120 I8 before a 320x240 RGBA8 overwrite; it failed with duplicated
quadrants before RecompCore `66fb61257f` and passed afterward. All 18 runnable
CTest contracts and six serial Metal fixtures passed, as did the build, signing,
patch/lock verification, and audit. The authentic replay remained stable but
changed zero synchronized pixels from the scaled-extent control. The cache fix
is retained for correctness and explicitly rejected as the black-world owner.

The decisive finding sat one layer earlier in those same material display
lists. Every primary material writes BP mask `0x001FE3` immediately before its
`PE_CMODE0` payload. J3D deliberately uses this one-shot hardware mask to
change blend factors while preserving dither, color-update, and alpha-update
bits installed by `J3DSys::drawInit`. Aurora and Dolphin both merge the next
write against the prior register value and then reset the mask. BlueWake's
shared retail frontend instead stored the raw payload, clearing the preserved
write-enable bits. Room geometry therefore updated depth while leaving the
black-cleared EFB color untouched, exactly matching the visible symptom.

A pure owner-level oracle first demonstrated the failure: initial `PE_CMODE0`
`0x001C`, mask `0x001FE3`, and J3D payload `0x003104` must produce effective
value `0x00111C` and reset the mask to all ones. RecompCore `f50c396aaf`
implements that contract centrally, records the effective value in traces, and
feeds the same value to replay and retail side effects. All 18 runnable CTests,
six serial native Metal fixtures, the complete build, audit, and strict signing
passed.

The exact same-boundary native replay then changed 1,570,472 pixels and raised
nonblank coverage from 761,938 to 2,018,016 pixels. Direct inspection shows a
bright blue ocean, textured island cliffs, sky, clouds, and vegetation where
the broad black world had been. The run preserved all guest milestones, made
1,302,398 submissions without a rejection, failure, or skip, and stopped
normally at retrace 14,200. This resolves the visual half of the Outset gate.
It does not yet prove player presence, sustained native control, audio, or
long-session stability, so `BW-P4-0059` remains open for that final control
qualification rather than being declared playable prematurely.

One earlier early-depth Metal fixture invocation trapped inside Dawn's Metal
bind-group submission. The fixture later passed in the serial six-fixture
qualification, and neither game replay crashed, so the event remains recorded
as intermittent backend-test risk rather than a guest-game terminal.

## August 29: The first full native-object DOL route

The performance work eventually changed scale. Instead of shaving another
helper boundary from the generated C route, BlueWake built DolRecomp's LLVM
backend on macOS and taught it to emit arm64 Mach-O objects directly. The
first complete Wind Waker DOL translation produced 6,571 exact-semantics
objects. A composite adapter then linked those native DOL objects beside the
existing tagged C REL output, retaining the same CPU state ABI, module table,
and address coverage contract.

The first authentic process failed almost immediately, but usefully. Wind
Waker raised its normal floating-point-unavailable exception at
`0x802AE070`, inside `JAIZelInst` construction. The host enabled MSR[FP] and
retried the saved PC, but LLVM's cold-entry switch admitted only structural
region leaders. Since the faulting `lfs` sat inside a straight-line region,
the retry fell into an interpreter that did not implement it. This was not an
allocator or host exception defect; it was a translator/native re-entry
contract gap.

DolRecomp now marks the first scalar FP load or store with an availability
helper in each structural region as a native entry. The narrower rule matters:
making every instruction an entry repaired the fixture but disrupted
optimization assumptions, while treating paired-single operations the same
way broke fixed-GQR tests. The promoted scalar rule passes the full 28-test
suite, including a focused fault-enable-retry fixture. A cache-disabled
regeneration then proved the fix at full-game scale, and IR inspection showed
`0x802AE070` mapped directly to its native block.

The next authentic run cleared that exception and completed 700 retraces in
25.49 seconds, demonstrating the route's performance potential. It also
prevented a premature victory: unlike the canonical C route, it never entered
`cDyl_InitAsync`, never mounted `RELS.arc`, and reached dynamic-module linking
with a null archive. Retail correctly called `PPCHalt`; the host then remained
there until the bounded stop. That result moved the active question upstream
from DVD and REL loading to CPU state at the earliest missing initialization
admission. The hybrid route remains a measured candidate, not the product
route, until its complete authentic digest matches. Evidence SHA-256:
`83afe924bfb613be8e53ae4ec42d3d52bf129a4555411962f02ff2292da759ee`.

through the slow path fixed that translator error, but the first full v25 run
still returned a null profile. The generated code was now asking the right
question; BlueWake had wired its answer to `host_mmio_read`, which knew only
devices and returned zero for every non-MMIO address.

The host promoted that boundary into a real external-memory gateway. It uses
the same guest RAM and alias resolution as the canonical C route, including
the masked form of tagged addresses, before falling through to MMIO. Writes
take the same route and retain reservation and memory-journal behavior. A
focused test reads profile `0x8039404C` through a tagged alias and writes back
through the same shared storage.

title flow. Process 5 allocated its 512-byte object, scene creation reached

## August 29: Optimization cost becomes a first-class constraint

With exact LLVM closed and the generated-C route still about three times
slower than real time in the longer signed run, the goal loop returned to the
latest clean profile. Donor DSP scheduling and translated execution owned most
main-thread samples. DSP cadence and isolated helper work were already closed,
but the full 748-unit C composite still carried the `-O1` setting chosen when
the first 18-million-line artifact was made buildable during P3.

An isolated full `-O2` build tested that subsystem-wide policy without changing
runtime semantics; `-ffp-contract=off` remained in force and the canonical
app/dylib were never replaced. The compile itself rejected the hypothesis. It
was stopped after 10,408.68 seconds wall, 52,800.43 seconds aggregate user CPU,
934.49 seconds system time, and 2,639,020,032 bytes maximum RSS. Three optimizer
jobs were still unfinished. A single REL translation unit had occupied a core
for the full 2h53m and one DOL unit for 45 minutes, demonstrating pathological
optimizer scaling rather than an ordinary slower clean build.

No candidate dylib existed, so this event carries no runtime correctness or
speed claim. The temporary build control was removed and the accepted `-O1`
source policy remained byte-for-byte unchanged. Whole-composite `-O2`, `-O3`,
and LTO are now a closed experiment shape until generated-code shape or
partitioning changes provide a bounded optimizer-cost hypothesis. This is also
part of the porting story: build feasibility is a product constraint, and a
promising profile owner is not permission to spend unbounded compiler time.
