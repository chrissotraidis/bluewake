# October 8 issue triage

The first pass after 0.6.0 was published, at `main` `7dd0b40`. It read the replies and logs posted
since the release notes went out, answered them on GitHub, and set the next steps in
[PRIORITIES.md](../PRIORITIES.md). Nothing here was tested on hardware: these are findings from player logs
and source. Reporter logs were read locally and are not committed.

## The bird scene: one cutscene, two problems (#65, #59)

Two logs reach the same cutscene, `[demo] start stage=sea event=251` (the Helmaroc King carrying Tetra,
after Aryll gives Link the telescope): minibeas's Mac M4 log on #65 (the 0.5.0 app) and fehnomenal's
Linux log on #107 (Ryzen 7 7840HS, NixOS, `[dvd] deferred completion=off`).

**Sound.** Both end with the same line, `frames=1384 cues=0 sounds=0 missing=0 silent=12.4s of 46.2s`.
At the scene's start the stream starts and stops two retraces later:

```
[music-stream] retrace=56116 path="Audiores/Stream/1tale.afc" id=0xC0000001 state=4 ... dvd_pending=1 starting=1
[music-stream] retrace=56118 path="Audiores/Stream/1tale.afc" id=0xC0000001 state=0 ... dvd_pending=1 starting=1
```

That is the history intro's failure before 0.6.0 (#97), and both runs lack the 0.6.0 fix (deferred DVD
completion). So 0.6.0 may fix this scene too. *Suspected, not checked*: nobody has reached this scene on
0.6.0. DonatelloEsq getting the sound back by turning settings off fits a timing race. Next: a 0.6.0 run
from a new file to this scene (asked on #65).

**Speed.** On Linux the scene runs at 4 to 20% game speed (`perf-summary`: lowest 4%, 160 seconds below
target, all `cause=game-thread`, all sea room 44); the game thread is at 99% and the GX worker at 8 to 48%.
It returns to full speed when the scene ends. On the M4 the same scene never drops below 99%. Windows
players reported the same slowdown (#59). A gap this large on one scene points at a slow path only x86
takes. *Suspected*: denormal floats. RecompCore sets x86 FTZ and DAZ only while the guest's FPSCR NI bit
is set (`GXRuntime/src/core/cpu_interpreter_float.c`), so with NI clear, x86 pays the denormal penalty
that Apple's cores don't. Next: `perf record -g` across the scene on Linux (asked of jkoehler11 on #59);
if the time is in floating-point code, an opt-in test that forces FTZ/DAZ on the game thread, compared for
speed and with the boot-route check.

## Native entries certify 0 of 15 (#179)

The report reads this as drift since `552ce1f`. That commit imported Elliott Tate's hashes from
Wind-Waker-Recomp's release pipeline, which made lean prepaid copies. BlueWake's `fast_blocks.py` makes
conservative ones, because the full transform failed the boot-route comparison on October 2, so the
hashed text never matches; October 7's run on the 0.6.0 Windows source also gave 0 of 15
([findings](FIXES_2026-10-07.md#performance-findings)). New hashes need the comparison tests
(`tests/native_*_test.c`) rerun against a BlueWake module, and those load a Windows DLL today. Suggested:
make them load a Linux `.so` so the Steam Deck work can run them.

## Cloud, wave and fog flicker (#136)

A second reporter (RTX 5070 Ti) answered the key question with video: clean at 30 FPS, flickering at 120,
and the fog in the Outset forest flickers too. *Cause narrowed*: the in-between frames Smooth Motion makes,
for draws with moving textures. Still not seen on the Mac.

## Controllers (#61, #155)

- #61: the one-line `gamecontrollerdb.txt` (the reporter's mapping without `crc:`) works, with B and X
  swapped. Asked him to fix B and X under Controller buttons on 0.6.0. The stock SDL_GameControllerDB line
  is what scrambles this controller.
- #155 (Windows 10, Mayflash in PC mode, 0.5.0): SDL's GameCube adapter driver opens four
  `Nintendo GameCube Controller`s (`vid 0079, pid 1844, type 11`), one per port. Twelve seconds in, all four
  are removed at once and never return, which happens when reading the adapter fails (unplugged, or another
  program holding it). Asked for a 0.6.0 log with the controller in port 1, and whether it was unplugged.

## Portable files (#64)

Aurora's user folder holds `imgui.ini`, `*.controller` remaps, `keyboard_bindings.dat` and
`controller_ports.dat`, and it always came from SDL's per-user folder. RecompCore #18 (patch 0160) adds
`DOL_AURORA_USER_DIR`; BlueWake #184 sets it on Windows and copies existing files into a portable folder
without overwriting.
